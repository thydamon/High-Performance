# 《Building Low Latency Applications with C++》学习计划

> 基于 *Sourav Ghosh*, Packt Publishing, 2023

## 🎯 学习目标

- 理解低延迟系统的核心概念、度量指标和 C++ 为何是首选语言。
- 掌握构建低延迟系统的基础组件：线程、内存池、无锁队列、日志、网络。
- 从零实现一个完整的电子交易生态系统：交易所撮合引擎 + 客户端策略。
- 学会使用 RDTSC 等工具测量、分析和优化延迟。

---

## 📋 前置要求

- 扎实的 C++ 基础（类、模板、STL、智能指针）。
- 操作系统基础（线程、进程、内存、网络 socket）。
- 基本的 Linux 开发环境（书中示例基于 GCC/Linux）。
- 推荐工具：GCC 11+/Clang、CMake、gdb、perf、Python（数据分析）。

---

## 第一阶段：打基础（第 1–3 章）

**目标：** 建立低延迟思维，理解 C++ 语言和编译器层面的优化方向。

| 章节 | 主题 | 重点内容 |
|------|------|---------|
| 第 1 章 | 低延迟应用开发导论 | 延迟 vs 吞吐、latency-sensitive vs latency-critical、C++ 优势（编译型、近硬件、资源确定性） |
| 第 2 章 | 常见低延迟应用设计 | 视频直播、游戏、IoT、零售分析、电子交易；重点是理解延迟来源 |
| 第 3 章 | C++ 低延迟视角 | 数据结构与算法、缓存与内存访问成本、类型选择、分支预测、内联、编译时多态、异常、编译器优化 flag |

### 实践任务

1. 用 `g++ -O0/-O2/-O3` 编译同一段代码，对比生成的汇编和运行时间。
2. 编写简单 benchmark，测试：
   - 顺序访问 vs 随机访问数组；
   - `std::function` vs 函数指针 vs 模板；
   - `virtual` vs CRTP（编译时多态）。
3. 用 `perf` 观察缓存未命中（cache misses）和分支预测失败。

### 预计时间

**1.5–2 周**

---

## 第二阶段：构建基础组件（第 4 章）⭐ 核心

**目标：** 实现低延迟系统常用的基础设施组件。

| 组件 | 重点 |
|------|------|
| 线程库 | `std::thread`、线程亲和性（affinity）、绑定 CPU core |
| 内存池 | 避免动态内存分配、预分配、对齐、回收策略 |
| 无锁队列 | lock-free queue、SPSC/MPSC 设计、内存序（memory order） |
| 日志框架 | 异步日志、环形缓冲区、避免锁和动态分配 |
| 网络 socket | TCP/UDP socket 封装、非阻塞 IO、zero-copy 思想 |

### 实践任务

1. 实现一个**固定大小的内存池**，对比 `new/delete` 和内存池的分配延迟。
2. 实现一个**单生产者单消费者（SPSC）无锁队列**，用线程交替发送 1000 万条消息，测量延迟分布（p50/p99/p999）。
3. 实现一个**异步日志器**：生产者写入环形 buffer，单独 logger 线程刷盘。
4. 用 socket 实现一个简单的 echo server/client。

### 预计时间

**2–3 周**

> ⚠️ 这一章是全书基石，建议慢下来吃透。

## 第三阶段：构建交易所端（第 5–7 章）

**目标：** 实现交易所核心：撮合引擎、订单簿、市场数据发布、订单网关。

| 章节 | 主题 | 重点 |
|------|------|------|
| 第 5 章 | 交易生态系统设计 | 交易所拓扑、撮合引擎设计、订单簿、市场数据发布、订单网关 |
| 第 6 章 | 撮合引擎实现 | 订单簿数据结构、新订单处理、撤单、撮合逻辑、与网关/行情队列交互 |
| 第 7 章 | 与市场参与者通信 | 行情协议、订单协议、行情发布器、订单网关服务器、FIFO sequencer |

### 实践任务

1. 实现一个**限价订单簿（Limit Order Book）**，支持 add/cancel/match。
2. 实现**撮合引擎**，处理市价单、限价单、撤单。
3. 设计简单的二进制协议（market data protocol + order protocol）。
4. 实现**行情发布器**（order book updates + snapshot）。
5. 实现**订单网关服务器**，处理客户端连接、请求路由、响应返回。
6. 将交易所端组件整合成一个可运行的 exchange binary。

### 预计时间

**3–4 周**

---

## 第四阶段：构建客户端策略系统（第 8–10 章）

**目标：** 实现客户端：行情消费、订单网关、仓位/PnL/风险管理、策略引擎。

| 章节 | 主题 | 重点 |
|------|------|------|
| 第 8 章 | 行情处理与订单发送 | 行情订阅解码、重建订单簿、订单网关客户端 |
| 第 9 章 | 策略构建模块 | Feature engine、Position/PnL 跟踪、OrderManager、RiskManager |
| 第 10 章 | 做市与流动性提取策略 | Market Maker、Liquidity Taker、Trade Engine、完整客户端运行 |

### 实践任务

1. 实现**行情消费者**，解码交易所发送的行情数据，重建客户端订单簿。
2. 实现**订单网关客户端**，发送新单、撤单，处理成交回报。
3. 实现**PositionKeeper**：根据成交更新仓位和 PnL。
4. 实现**OrderManager**：管理活跃订单、去重、状态机。
5. 实现**RiskManager**：最大仓位、最大亏损等风控检查。
6. 实现两个策略：
   - **Market Maker**：双边报价，赚取买卖价差。
   - **Liquidity Taker**：基于信号主动吃单。
7. 将客户端组件整合成可运行的 trading client binary，与第三阶段做的交易所对接。

### 预计时间

**3–4 周**

---

## 第五阶段：性能测量与优化（第 11–12 章）

**目标：** 给系统加插桩，量化延迟，分析瓶颈并优化。

| 章节 | 主题 | 重点 |
|------|------|------|
| 第 11 章 | 插桩与性能测量 | RDTSC 时间戳、各环节延迟测量、交易所/客户端全流程 latency tracking |
| 第 12 章 | 性能分析与优化 | 数据分析、release build、线程亲和性、日志字符串优化、避免 `std::function`、容器预分配、hash map 优化、snapshot 优化 |

### 实践任务

1. 在交易所和客户端的关键路径加入 **RDTSC 时间戳**（行情接收、撮合、发响应、客户端处理、下单等）。
2. 运行完整生态系统，收集 latency 数据。
3. 用 Python（pandas/matplotlib）画出延迟分布图。
4. 针对性优化：
   - 线程绑定到指定 CPU；
   - 关闭 logger 或优化为无锁；
   - 预分配 vector/unordered_map；
   - 替换 `std::function`；
   - 使用内存池。
5. 对比优化前后的 p50/p99/max 延迟。

### 预计时间

**2–3 周**

## 💡 学习方法建议

1. **边读边写**：不要只读，每看完一章就把代码自己敲一遍。
2. **先跑通，再优化**：先让程序正确运行，再追求低延迟。
3. **量化一切**：学习过程中持续测量，不要凭感觉优化。
4. **做笔记**：把每个组件的接口、关键数据结构、延迟来源整理成文档。
5. **对比书中实现与自己实现**：思考为什么作者这样设计，有没有更好的方式。
6. **延伸学习**：
   - 阅读 `memory_order` 和 C++ 内存模型；
   - 学习 `perf`、`tcpdump`、`strace` 的使用；
   - 了解真实交易所协议（如 FIX、ITCH、OUCH）。
